ここまで、エージェントは自分の EC2 の上で動いていました。それを AWS のマネージド環境（AgentCore Runtime）に載せ替えます。

## 手順

<Steps>

1. エディタのメニューから Terminal → New Terminal でターミナルを開きます。`/home/handson/workspace` が開いた状態になっています。この場所のまま打ちます。

2. 次の 1 行を打ちます。

   ```bash
   agentcore deploy
   ```

3. 2〜3 分かかります。その間に、Runtime が何を引き受けてくれるのかの話を聞いてください。ターミナルに `Deployed` のような表示が出て止まったら終わりです。

4. ハンズオン UI のページを再読み込みします。入力欄の上に「手元で動かす / Runtime で動かす」の切り替えが増えています。

5. 「Runtime で動かす」に切り替えて、前半と同じ質問を送ります。

   ```text
   モニター借りたいんだけど空いてる？
   ```

</Steps>

## 前半との比較

![前半は自分の EC2 の中でエージェントが動き、後半は同じコードが AgentCore Runtime の中で動く。ブラウザと UI のサーバーは変わらない](/images/local-vs-runtime.png)

画面の見え方は前半とまったく同じです。緑のカードに「お題（Runtime）」と出ているところだけが違います。

自分で足した `find_available` も、そのまま Runtime 側で呼ばれます。載せたのは、さっきまで手元で動いていた自分のエージェントそのものです。

違うのは動いている場所だけです。前半は自分の EC2 の中で Python が動いていました。今は AWS 側の箱の中で同じコードが動き、EC2 はそれを呼びに行っているだけです。

## Runtime の役割

手元で動いているものを他の人に使ってもらうには、いろいろ要ります。サーバーを立てて、認証を付けて、同時にたくさん来ても耐えて、落ちたら上げ直す。それを全部引き受けるのが Runtime です。

いま打ったのは 1 行でしたが、裏では次のことが起きていました。

![agentcore deploy の裏側。handson-agent のコードを zip にまとめて S3 に置き、AgentCore Runtime と実行用の権限、呼び出し口を作る。呼ばれるたびに、セッションごとに分かれた実行環境で zip のコードが動く](/images/deploy-inside.png)

1. `handson-agent/` のコードが zip にまとめられました。
2. その zip が S3（AWS のファイル置き場）に置かれました。
3. AgentCore Runtime が作られ、外から呼ぶための呼び出し口と、実行用の権限が用意されました。ここまでが deploy の 1 回だけで起きることです。
4. Runtime は呼ばれると、セッション（ひとまとまりの会話）ごとに分かれた実行環境を用意し、その中で zip のコードを動かします。

前半のループのコードは 1 行も変わっていません。

:::note[コンテナとの関係]
Runtime にエージェントを載せる方法は 2 つあります。

1 つはコンテナで渡す方法です。Dockerfile を書いてコンテナイメージを作り、ECR（コンテナイメージの置き場）に上げてから Runtime に渡します。業務でコンテナを使っている人には、こちらのほうがなじみがあると思います。

もう 1 つが、今回使ったコードを zip で渡す方法です。コンテナイメージは作らず、Dockerfile も ECR も要りません。

どちらの方法でも、動く場所はセッションごとに分かれた実行環境（microVM という軽い仮想マシン）です。ほかの人の会話のデータが混ざることはありません。
:::

:::note[deploy が失敗した場合]
もう一度同じ `agentcore deploy` を打つと、続きから進むことが多いです。それでも止まるときは、ターミナルの最後の数行を主催者に見せてください。
:::

:::note[質問を送ってメッセージが出た場合]
他の受講者と質問のタイミングが重なると、画面に「モデルの呼び出しが混み合っています」と出ることがあります。少し待ってから、もう一度同じ質問を送ってください。
:::
